# miguelluzes.github.io

Miguel Luzes's personal site. Plain HTML/CSS/JS generated from Markdown content by a small
Python build script — no npm, no framework, deploys to GitHub Pages via GitHub Actions.

Why Python instead of Astro (as originally planned in `PLAN.md`): this repo was first built in a
sandboxed environment with no access to the npm registry. Jinja2 + Markdown + PyYAML were already
available and produce the same result — static HTML/CSS driven by Markdown files with frontmatter.
Functionally it's the same site described in `PLAN.md`; only the build tool changed. If you'd
rather move to Astro later, the content files in `content/` translate almost directly into Astro
content collections.

## Run it locally

Requires Python 3.10+.

```bash
pip install -r requirements.txt
python3 scripts/build.py
cd dist && python3 -m http.server 8000
# open http://localhost:8000
```

Re-run `python3 scripts/build.py` after any content change, then refresh the browser. There's no
watch mode — for quick iteration, keep a second terminal open with:

```bash
# macOS/Linux, requires entr (brew install entr / apt install entr)
find content templates static -type f | entr -r python3 scripts/build.py
```

## Add a blog post

Create `content/blog/my-post-slug.md`:

```markdown
---
title: My post title
date: 2026-10-01
description: One sentence for the list page and RSS.
category: books   # books | gym | movies | football | life | data
draft: true        # set to false (or remove) to publish
---

Body goes here, plain Markdown.
```

The filename (without `.md`) becomes the URL slug: `/blog/my-post-slug/`.
Posts with `draft: true` are built (so you can review them at their URL) but excluded from the
`/blog` list, the homepage, and the RSS feed. Flip to `draft: false` when ready.

## Add a lesson (Learn section)

Create `content/learn/my-lesson-slug.md`:

```markdown
---
title: My lesson title
date: 2026-10-01
description: One sentence.
topic: SQL          # SQL | Power BI | Python | dbt
level: beginner      # beginner | intermediate | advanced
draft: true
---

Body goes here. Use fenced code blocks for examples:

​```sql
SELECT 1;
​```
```

## Add a project

Create `content/projects/my-project-slug.md`:

```markdown
---
title: My Project
summary: One sentence for cards and meta tags.
year: "2026"
featured: false      # true puts it in the homepage's top 3 — keep that to 2-3 max
order: 8              # controls sort order on /projects (lower = earlier)
stack: [Python, SQL]
github: "https://github.com/miguelluzes/my-project"   # optional, omit or leave "" to hide
demo: ""
report: ""
---

## The problem
...
## What I built
...
## Results
...
## What I learned
...
## Stack
...
```

If you want a diagram, copy the inline `<svg>` pattern from an existing project file inside a
`<div class="diagram">...</div>` — plain SVG, no library, works in light and dark mode via
`stroke="currentColor"`.

## Update the CV

Edit `content/cv.yaml` (experience, education, voluntary work, skills, certificates). The
`/cv` page and the downloadable PDF are separate — update both when your CV changes:

1. Edit `content/cv.yaml` for the on-page version.
2. Replace `static/Miguel_Luzes_CV.pdf` with a newer export. **Never include a phone number in
   that PDF** — the CI build fails on purpose if one slips into the built site.

## Update Uses

Edit `content/uses.md`.

## Site-wide settings

`site.yaml` at the repo root: your name, tagline, about blurb, email, GitHub/LinkedIn URLs, and
the "Currently" bullets shown on the homepage.

## First-time setup (GitHub Pages)

1. Repo must be named exactly `miguelluzes.github.io` (or your chosen username + `.github.io`).
2. Settings → Pages → Source → **GitHub Actions**.
3. Push to `main`. The `deploy.yml` workflow builds and publishes automatically.
4. If your GitHub username differs from `miguelluzes`, update `base_url`, `github` in `site.yaml`,
   and the repo name to match — the URL is always `https://<username>.github.io`.

## Project layout

```
content/            Markdown + YAML content (edit this to change the site)
  projects/*.md
  blog/*.md
  learn/*.md
  uses.md, cv.yaml
templates/           Jinja2 HTML templates (edit this to change layout/design)
static/               CSS, JS, favicon, CV PDF, OG image — copied as-is into the build
scripts/build.py     The static site generator
site.yaml             Global site settings
dist/                 Build output (git-ignored, regenerated by build.py)
```
